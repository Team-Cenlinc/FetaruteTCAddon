# 站场图屏（yard-3x5、yard-4x8）

站场图屏把一个车站，或一个控制区里的几个车站与车库，画在地图屏上：轨道拉直成横向示意图，按占用着色，车身与车次窗叠在上面，底部是图例。它是站台屏的一种布局，安装、绑定、主题和刷新都沿用站台屏。

| 布局 | 地图 | 像素 | 适合 |
|---|---|---|---|
| `yard-3x5` | 3 行 5 列 | 640×384 | 单个车站 |
| `yard-4x8` | 4 行 8 列 | 1024×512 | 控制区（两三个车站或车站加车库） |

只读：不改占用、不碰列车。信号员控制台（`signalbox-3x5`、`signalbox-4x8`）在它的基础上加了列车表、操作按钮、入口信号与进路预显示，见 `signaller.md`。

`signalbox-*` 是信号员控制台，不是站台屏：用 `/fta signal console` 领安装纸、绑定控制区与拆除（见 `signaller.md`），`/fta pids` 不管它。它的站场图与 `yard-*` 同一画法，另叠加：选中车的计划进路（浅蓝；浅色主题用深蓝）、已给许可还没放行的进路（白色虚线）、控制区入口信号（8×8 方块，红/黄/绿，设了自动通过的旁边写 “A”）、选中车可改停的股道（空心方块，现在要停的实心）、选中车的车次窗加琥珀色框。点击只在 `signalbox-*` 布局上生效：右键是“按”，左键是“取消选择”，同一 tick 的重复事件只算一次，命中由布局与画面数据推出（`PidsSignalboxPlan`），点击区不小于 16×16 像素。控制台的帧不进共享帧缓存，点击后当拍重画这一块屏。

## 安装与绑定

1. `/fta pids give yard-3x5`（或 `yard-4x8`）领安装纸，在挂满空展示框的墙上右键。
2. 安装时自动绑定附近的车站；附近没有车站时和车站统屏一样不能安装。之后可以用配置棍或 `/fta pids set <屏幕> station ...` 改绑；站场图屏也可以只绑运营商（`/fta pids set <屏幕> operator <运营商>`），再绑控制区。
3. 要画控制区：`/fta pids set <屏幕> zone <控制区>`（屏幕所属运营商名下的控制区；`none` 解绑）。绑了控制区时以控制区为准，标题写控制区名；改绑到别的运营商时控制区自动解绑。配置棍菜单里站场图屏有“控制区”一行。
4. 装好后是测试卡，`/fta pids set <屏幕> mode live` 切到运行显示。车站与控制区都没绑的站场图屏一直显示测试卡。

## 控制区

控制区是运营商名下的一片站场：若干车站与车库，将来也是信号员的辖区。用 `/fta signal zone` 维护：

| 命令 | 作用 |
|---|---|
| `create <公司> <运营商> <代码> "<名称>" ["<英文名>"]` | 新建；代码在运营商内唯一（不分大小写，存为大写），不能含冒号 |
| `list <公司> <运营商>` | 列出控制区与成员数 |
| `info <公司> <运营商> <控制区>` | 查看成员 |
| `rename <公司> <运营商> <控制区> "<名称>" ["<英文名>"]` | 改名称（不写英文名即去掉） |
| `add\|remove <公司> <运营商> <控制区> station\|depot <代码>` | 加入或移出车站、车库 |
| `delete <公司> <运营商> <控制区> --confirm` | 删除；绑定它的站场图屏改显示“未找到绑定的控制区” |

- 改动要能管理运营商所属的公司；`list`、`info` 要能读取。
- 成员只能是同一运营商的车站或车库。车站要在库里登记过（写回登记的站码）；车库在库里没有实体，按调度图里的 `运营商:D:车库:股道` 节点核对，所以要先建图。
- 成员按“种类 + 代码”记，不连外键：车站改代码或删掉后成员不跟着变，画图时找不到的成员直接略过。删运营商或公司时它的控制区一并删除。
- 站台屏只按运营商代码认运营商：两家公司有同代码的运营商时，与车站目录一样先到先得，站场图屏只查得到那一家的控制区；`/fta signal zone` 命令按公司 + 运营商查，各家的都查得到。
- 存储：`control_zones`（运营商 + 代码唯一）与 `control_zone_members`；站台屏的 `pids_screens.zone_code`。控制区在内存里有一份目录（`ControlZoneDirectory`），启动时与改库后整体重读，站场图屏每次检查只查内存。

站场图屏不能与其他布局组合翻页（`PidsScreenPages#combinable`），也不轮播公告。

## 画哪些轨道

站场由调度图推出来（`YardArea`），不需要手工登记：

- 起点是成员车站的站台节点（`运营商:S:站:股道`）与咽喉节点（`运营商:S:站:股道:序号`），以及成员车库的股道（`运营商:D:库:股道`）与咽喉节点。只绑车站时成员就是这一个车站。
- 沿区间向外展开：道岔节点与无名目的地节点算在站场内，但离最近的起点超过 256 格的不算。没有区间点隔开的正线因此不会把整条线卷进来。
- 两端都是成员车站的区间点算在站场内，控制区里相邻的几个车站因此连成一张图。
- 控制区里两个车站之间若要经过别的区间（例如一条线在另一条线的区间中途岔出），再试一轮：只有一端是成员车站的区间点、以及经由它们走到的道岔先算进来；只留下把两个不同成员连起来的几片，再把走不回区内的支线一段段剪掉。两条区间朝同一侧离开的道岔（两条线汇合后同去一站，从一站到另一站要折返）也剪掉。四周全是第一轮站场内节点、碰到两个以上的一片也留下（只绑一个车站时这一轮也做，留下的只有这种）：它夹在站场内两处之间、不往外伸，典型是站台与本站咽喉之间隔着的头一个区间点（去掉了站台与咽喉就断开，两头都成了出口）。
- 碰到其余的区间点、别的车站、车库或跨世界节点就停下，这条区间算出口，只画靠站场的 24 格，末端写去向（区间点取不是成员车站的那一端，按站名显示，查不到写站码）。
- 站场内节点超过 512 个时不再展开。

道岔节点的 ID 只有坐标、不带车站，所以只能这样按拓扑推。

## 怎么画

几何（`YardGeometry`）按信号楼示意图排布：股道画成水平的行，股道之间用斜线相连（跨一层的是 45°，跨好几层的更陡；U 形联络线的折返处竖着连），区间中间的弯道一律拉直。它只依赖调度图快照，图重建、刷新或增补后才重算：

- **直股**按优先级定，后一级只补前一级没定的节点；找进路时都按行车方向走，不在道岔处折返：
  1. 道岔群里区内两站之间的进路（`routeThrough`）：线路分叉的道岔群（见下文“线路分叉”）往外通往的几处里只有两处是区内车站、其余都是出口，并且来路是其中一站时，两站的各股经群内的道岔两两接起来，先取群内路程最短的，各条进路不共用节点；一股走到另一站某一股的外端时经别的股更近（这股绕远路汇进来）就不接，那股交给道岔几何。接上的进路在途经的各道岔定为直股，不看几何：实地往出口一侧直着走、往区内一侧拐过去时，正线也照样画成一条直线，出口从旁边岔出。
  2. 同一区间相邻两个区间点之间的进路（`followIntervals`）：区间点的名字写着区间、股道与序号，同一区间相邻的两个（同一股道上下一个有的序号，或整条区间里下一个有的序号，中途换股道也接得上）之间只经道岔的进路，途经的道岔按这条区间定直股。先配同一股道的，再按路程从短到长；各条进路不共用节点，经过分叉群或第 1 级已定节点的不用，在节点处两条朝同一侧离开（V 形）的不算。道岔两股夹角只差一两度、几何上分不出直股侧股时，正线因此照线路画成直线。出口外端的区间点也算，出口因此接在它进站的那一行上。
  3. 其余按道岔几何（`throughLinks`）：只连一条区间的就是那一条；只连两条的两条都是，两条朝同一侧离开（V 形）的没有直股；三条以上的先看所在的轨道方块（`face`）：轨道只能从方块的四个面接出去，从相对两面接出去的两条就是直股，另一条是侧股，从道岔处拐出去。哪条区间从哪一面接出去，看那一面的邻格是它的、并且从邻格还接着往外有它的格子（道岔周围几格常被各条区间都带上，只看邻格分不清）。认不出、或相对两面的两条朝同一边离开（V 形，例如两条渡线汇到中间一段）时，看各条区间离开它 2 到 16 格内轨道方块的重心走向，最接近一条直线的两条是直股——重心会被出了道岔就拐弯的正线带偏好几度，缓的渡线与弯走的正线这样分不清，所以先看接出去的面。分叉群里岔出去的各股不当直股。
- **行**：直股连成的一条链整条占一行，几个车站之间的同一条正线因此画成一条直线；落在同一条股道延长线上（真实横向偏差不到 1 格）的站台股道并为一行。其余各段：只接在一行上的（出口短线、尽头侧线）按离接点的横向偏移排在那一行旁边；接在几行之间、实地夹在最上与最下两行的接点之间的（渡线中段、剪式渡线的交叉；各按接点处量的横向位置，差 1 格以内也算）排在这两行正中，同一组交叉的几段共用这一行，画成 X——交叉的节点实地常紧挨一股道，按自身横向位置排会贴着那一股拆成几层台阶；其余的按自身横向位置。
- **线路分叉**不分主次。不属于车站、车库、出口而连着三条以上区间的道岔，彼此相隔不超过 32 格的并成一群（复线分叉常由几组道岔组成，上下行之间还可能有渡线或平交）；这一群往外伸出的各股沿线最先到的车站或出口（去车库的不算）有三处以上不同，就是分叉；出口按它通往的车站算一处，复线的两条出口去同一站不算两处（认不出去向的各算各的）。通往同一车站不同股道的咽喉、上下行之间的渡线往外只到两处，不算。几处里只有两处是区内车站、其余都是出口，并且来路是其中一站、两站之间经群内接得上进路时，也不算：那是正线旁岔出区外的支线，正线按上文“直股”第 1 级直着接过去，出口从旁边岔出；来路本身是出口、两站之间接不上，或有三处以上是区内车站时，照样是分叉。往外各股按通往的地方分组，离开方向与其余各组最相反的一组是来路，其余都是岔出去的：来路那一行在群里结束，岔出去的各股哪怕有一股在实地顺着来路直着走，也一律不当直股，都在群外各起一行、各占一层，不与来路首尾相接，也不因站台落在来路延长线上而并进来路那一行，从分叉处朝同一方向斜着分开，画成 Y 形。有分叉时整片的脊线取分叉来路一侧最长的一条链，按来路自己的走向定头尾，车站因此按实地先后排开（例如南北向的来路在左、过了分叉往东拐的一股与直着往南的一股都在右边），不会因为最长的一条链在某一股上而把来路排到另一头。岔出去的各股各用自己最长的一条链作脊线：每个节点归到沿轨道最近的那一股，里程在这一股伸出分叉的几处与来路的里程对齐、接着往外排，横向位置按这一股自己的走向量——往东拐的支线接在南北向的来路上时，支线上东西向车站的几条股道照样按南北分出上下，开门方向也按东西向判断。各股按在整片脊线上的平均横向位置排先后、整体错开，各股的行排层时不互相穿插，两股时来路夹在中间。
- **层**：各行按横向位置从上到下压进尽量少的层。横向范围不重叠的行共用一层（不相连的两行之间还要隔开 8 格）；首尾相接的两行各至少 4 格长时接在同一层、画成一条直线。再自下而上把每行压到紧挨着下面与它重叠的那一行。接上后画出的水平线若与别的区间重叠（道岔群里常见），或有区间因为几种 45° 摆法都会叠线而只好退成斜线，这几行改为不接、重排，最多重试三次。层距最多 32 像素，层数越多越密；层多到要压缩层距时，最上、最下两层外侧各留出一块侧式站台（17 像素）的位置，站台块不会落到站场图外面。
- **横坐标（沿线拉直）**：直股连成的最长一条链作脊线，按轨道长度展开成水平（东西走向东在右、北在上，南北走向南在右、东在上），所以弯道和几个车站之间的拐弯都拉直，不同走向的车站各自的股道也分得开。其余的链从接在已排好节点上的那一点（侧股从它岔出的道岔，或平行线之间的渡线）起，顺着离开的方向排，按垂足定先后、按离脊线的距离定上下；接进来的方向和链几乎垂直、分不出顺逆时，按链在脊线走向上朝哪边排。垂足挪不动（斜着岔出去的支线），或挪得比轨道长 1.5 倍以上（和脊线几乎垂直的库线，垂足落到了脊线的别处），就改按轨道长度接着排，库线因此排在分岔道岔后面、不会往回走。“挪不动”指挪了不到半个区间长，这个区间长取轨道长度与两头直线距离中短的那个：道岔区里由弯轨拼成的短区间（剪式渡线的交叉）轨道比两头实际隔开的长一倍多，按轨道长度量会把交叉点推过另一头的道岔。经线路分叉接得上的链先接，岔出去的各股因此都从分叉处顺着排，不会先被车站另一头的渡线带着反过来。一条链两头都接在已排好的线上（三角线里两条支线之间的联络线、迂回线），从一头按轨道长度排出去会把另一头连着的节点拉开 64 格以上（扣掉那段区间本身的长度）时，改为另一头也从它那边接过来，再看两头离开的走向（按下一个节点的垂足）：一路朝一个方向时，途经车站的站台与咽喉节点取垂足、和同站别的股道对齐，其余节点在相邻两个定好的节点之间按轨道长度均摊，不再冲过下一站再折回来；两头走向相反时是 U 形（例如三角线的联络线从两站靠分叉的一头出站，绕回分叉附近再拐向另一站），按各区间点实地位置的垂足排：垂足最靠外的点是折返点，两头到折返点各一路朝一个方向（往回挪的垂足压平），在折返点处断开成两行，折返处两头的节点各自占列。这样两头的站台各留在本站，联络线从站台靠分叉的一头伸出去再拐上去，不从站台上横穿。断开处那条区间画成“⊂”形：两头沿本行往外走到实地折返最远处（这条区间的轨道方块投到折返点所在那股的局部坐标上，最靠外的里程，再按两侧的列插值成横坐标），在那里竖着连上下两行，拐角切成 45°；它不占两头之间的横向距离，也不从两头之间斜穿过车站与别的线。外伸的水平部分会顺着别的线走、或伸出画面时，照普通区间画。互不相连的几片轨道各取各的脊线，从最长的一片起，依次贴到离它最近、已经摆好的那片上。相邻两处的距离按平方根压缩，长直线段缩短、道岔密集的咽喉相对拉开，并保证跨一层的区间有足够的横向距离画成 45°，跨好几层的只按层数的平方根留（斜线变陡：一条横跨全图的联络线不会把道岔区拉得比车站还宽），每个站台节点两侧各留 32 像素放站台（同一层相邻的也是站台股道时两块各要一份、共留 64 像素；邻居是岔出斜线的道岔时再多留一个层距）。链中间只连两段直股的经过点（区间点、咽喉点）不单独占位置、也不挡站台块，按里程插在前后两点之间，一长串区间点不会把出入库线或正线拉长。
- **区间**：两端同层画一条水平线；不同层画水平线加一段 45° 斜线，斜线贴着分出这条侧股的道岔，判断不出时放在中间。水平部分不许顺着同一层别的股道走，也不许和前面已排好的区间的水平部分叠在一起（否则看不出是两条线），依次换到另一头、中间试；都不行或横向距离实在不够时直接连斜线。例外：两条斜线的水平部分连着同一个节点（V 形道岔两条朝同一边离开的区间，例如剪式渡线中间的两组道岔）时可以叠在一起，画成两股并成一股的 Y 形，这正是它们在地面上的关系。
- **车库**（控制区里的车库成员）：库线、紧挨库线的本库咽喉点和有两条以上区间连进来的分岔道岔圈成一片，外面围虚线框，框里左上写“<库名>车库”（库名按车库代码查站名，查不到写代码），每条库线尽头写“库 n”，只连一条区间的尽头画车挡。一座车库分成几片时（例如有一条库线从咽喉的另一组道岔岔出），库名只写在库线最多的那片。库号写在尽头外侧，压到站台块或别的字时改写在尽头上方，仍压到就不写。排横坐标时给库号留位置：车挡尽头到同一层朝外最近的节点之间至少 40 像素，尽头在图的最左、最右一列时在图边留出同样的宽度。
- **库线超过 4 条的车库**收成一块面板：库内节点不再照画，从库外连进来的区间画到库门为止；面板贴着库门朝外伸，第一行写库名，以下每条库线一行短条（库号写在左边），短条按占用着色，库线上的车厢落在短条上，库门里道岔之间的车厢落在库门处。排横坐标时库门到朝外那一侧下一列之间至少留出面板宽度（任何一层的节点都算），库门在最边一列时在图边留出。两头都通库外的车库（库线另一头接着库外）照样收：库门在链中间也单独占一列，库线只朝库内画；这时面板朝外伸的那一侧还有库外的线，会从面板上穿过（线画在面板之上）。面板只在横向留位置，竖向盖住的几层上若有别的线经过，也是画在面板之上。
- **车厢**：按它沿轨道走过区间的比例，落到这条区间画出来的线上。
- **去向**：同名的几条出口只写一个：同属一片咽喉的（几条去同一处的线从同一组道岔分出去），或末端在图的同一半边、横竖都相隔不超过 96 像素的（复线两条）。一片咽喉指经道岔、区间点连着（不经车站、车库）的节点，出口归到它在区内那一头所在的一片；几条出口通到区外同一个节点（例如一个区间点既接着站台端、又接着站外的道岔）也算一片。离得远、又不在同一片咽喉的（同一车站从两处出区）各写各的。
- **站台**：每个站台股道旁画一块面板色的站台，块里靠左写股道号（“1 道”）；图里有几个车站时，每块站台的第一个股道号前面都写站名（“镇西 1 道”）。站台以站台节点为中心向两边各伸 72 像素，不越过同一层相邻的节点（相邻的也是站台股道时在两者正中分界），经过块的上下范围的斜线把块的左沿或右沿推开（节点两边至少留 8 像素），线不会压在站台与股道号上。
- **岛式还是侧式**：图里没有站台本身的数据，站台在哪一侧先看 AutoStation 牌子第 4 行写的开门方向（建图时记在节点上，`rail_nodes.door_direction`；按世界方位投到这条股道的横向上）。同一车站上下相邻的两条站台股道（最多隔一层，例如中间夹着渡线的交叉点）开门相对，或写了 `BOTH`，就当作两线共用的岛式站台、画在两层之间（上面一条的股道号写在块的上沿、下面一条写在下沿）；只有一条写了、朝着对方开也算，有一条背着对方开就不算。侧式站台画在开门那一侧。两侧都开门的股道可以同时是上下两块岛式站台的一边。
- 两条站台股道中间夹着别的区间的轨道（例如不停站的正线，按联锁的方块索引查），不管开门方向怎么写都不当作一块岛式站台。
- 岛式站台一般只配最多隔一层的下一条线；两条都写了开门方向、面对面开时不限层数（两行之间在站台处本来就没有别的线）。
- **没写开门方向时**按轨道间距推断：两条都没写、相隔至少 9 格才当作岛式（两侧式站台的两条股道常常只隔 4 格，中间空着或只有栏杆；中间再夹一条不停站的正线也只有 8 格，而那条正线不一定在调度图里）；侧式站台放在放得下的一侧，两侧都放得下时放在离邻线更远的一侧（图边算无限远）；上下相邻的两条按这个规则都要放进它俩之间的同一条缝时（例如四条股道相隔 4、8、4 格，中间两条外侧都只隔 4 格），两块会叠在一起，改画成两线共用的一块岛式站台。间距按节点旁最近的轨道方块量：节点坐标取的是牌子，常在轨道外侧或下面差一两格。
- 开门方向是新加的节点字段，旧图要重建调度图才会记下；记下之前按间距推断。改牌子上的开门方向会经增量同步写进库，但不算图的变化，下次载图（建图、刷新或重启）后站场图才跟着变。
- **站台文字放不下时**：依次改写“站码 1 道”“站码 1”，股道号也只写数字，都放不下才截断。同一车站只要有一块站台写不下站名，这个车站的站台就都改写站码，免得一站两种写法。
- **能放几个车站**：按实服线路试画，沿一条线排开的车站，yard-3x5（640×384）放 6 个时最窄的站台块还有 42 像素，yard-4x8（1024×512）放 8 个时还有 48 像素；4x8 放到 10 个时站台块只剩 24 像素，站码也会截断。车站带大咽喉、车库时能放的更少。
- 道岔走向与车厢定位都要用到建图时记下的每条区间的轨道方块（`rail_edges.footprint_json`，运行时从 `RailInterlockingState#footprintCellsByEdge` 取）。区间没有轨道方块（旧图还没按新格式重建）时照样画，但道岔走向只能按两端节点判断、这些区间上的车厢也无法定位，图左下角提示“部分区间缺少轨道几何”。重建调度图即可修正。

每次刷新（`YardProvider`）现取的部分：

| 画法 | 颜色（深色 / 浅色主题） | 来源 |
|---|---|---|
| 空闲 | 灰线 2 像素（`outline`） | 没有下面任何一种占用 |
| 进路锁闭 | 白 / 黑线 2 像素（`text`） | 区间（EDGE）资源上有 `MOVEMENT_REQUIRED` |
| 保护占用 | 暗红 `#993333` / 粉红 `#F27FA5` 线 2 像素 | 区间资源上有 `PROTECTIVE_RETAIN`、`HOLD_ONLY` 或 `PHYSICAL_FOOTPRINT`；与进路锁闭同时存在时按保护占用画 |
| 车占用 | 红线 3 像素（`red`） | 各节车厢所在的轨道方块（TrainCarts 的 `RailState#railBlock`）：车厢按它沿轨道走过区间的比例落在这条区间画出的折线上，连续在图上的相邻两节沿画出的轨道连（拐弯、U 形折返处不抄近路） |
| 车次窗 | 面板色底、左边线路色条 | 车头上方，压到别的车次窗或站台块时改放下方（上下都压到站台块时只避让车次窗）；文字为车次：自动生成的列车名（`SURC-MT-LP-4079`）取末尾 4 位序号，别的名字按表运行时写车次号，否则写列车名；晚点超过 1 分钟琥珀色、超过 5 分钟红色（`Lateness`） |
| 站台 | 面板色块，股道号为次要文字色 | 见上文“站台” |
| 车库 | 虚线框为 `inverseMuted`，库名、库号为次要文字色，车挡同空闲线色；面板为面板色块 | 见上文“车库”；文案 `pids.board.yard.depot`、`depot-track` |
| 去向 | 次要文字色，铺底色 | 出口末端下方，碰到下边缘或压到股道线、股道号、别的去向、信号员控制台的入口信号时改在上方；站名上下都放不下时改写站码，仍放不下就不写；同名的几条只写一个，见上文“去向” |

排队位、前瞻预览与解锁预约不画；节点（NODE）与冲突组（CONFLICT）资源不画。只画已加载、带调度标签的列车（`ManagedTrains#isFtaManaged`）。

## 刷新与开销

- 跟站台屏一样按 `pids.yml` 的 `render.check-interval-ticks`（默认 20 tick，即每秒一次）检查；内容标识（几何按对象身份、占用与列车按值）没变就不重画、不发送。
- 几何按“图快照 + 车站或控制区成员 + 画布区域”缓存，同一世界的各站共用一份按区间整理好的轨道方块；改控制区成员后按新成员重算一次。
- 几何在插件的异步任务里算（站场推导、拉直、站台、车厢定位都只读图快照），不占主线程；图重建后算好之前照旧显示上一张图，第一次画时显示“正在绘制站场图”。重算时顺手清掉旧图的几何与轨道方块，不让旧图一直留在内存里。
- 全网占用整理成的区间标记与每个世界的列车位置半秒内由各块站场图屏共用（`OccupancyManager#snapshotClaims` 半秒最多取一次）；车次号、线路色与晚点只查车身落在图上的车。
- 站场图的帧车一动就变、以后不会再用，不进各屏共享的帧缓存（免得把站台屏轮播可复用的帧挤掉）。车在动时每秒重画一次，只重发变化的地图块。
- 整帧渲染与调色板换算不在主线程：主线程每次检查只取数（占用、列车、控制台状态，都是快照），缓存里没有的帧交给站台屏的渲染线程（`FTA-PIDS-Render`，一个线程，所有站台屏共用）画，画好后在下一个 tick 写到屏上（`PidsFrameQueue`）。每块屏同一时间只画一帧，期间内容又变了只画最新的。信号员控制台点击后的新画面因此晚一个 tick 出现，点击按正显示的那一帧认。按实验服采样，站场图屏与控制台有人看着时各约 2–4 ms/秒的渲染因此离开主线程。
- 不做闪烁、不做悬停效果，避免持续重画。

## 布局键

```yaml
- type: yard
  x: 0          # 必填
  y: 32
  width: 640
  height: 268
  inset: 6      # 轨道距组件边缘的留白，默认 6；上方另留一行车次窗的高度
  label: 10     # 股道号、车次窗与去向的字号，默认 10
- type: yard-legend   # 两行样例加一行说明，贴着底边
  x: 0
  y: 300
  width: 640
  height: 84
  label: {size: 12, secondary: 10, gap: 6}   # 图例文字（中英文同行）
  note: 10                                    # 车次窗颜色说明的字号
```

站场图屏只能放站名（`station-title`，绑了控制区时写控制区名）、时钟、站场图与图例；图例离开站场图会被拒绝。去掉留白后画轨道的区域不足 32×32 也会被拒绝。

`yard-4x8` 的站场图为 `x: 0, y: 32, width: 1024, height: 396`，图例为 `y: 428, height: 84`。

## 屏幕上的提示

| 提示 | 原因 |
|---|---|
| 调度图未就绪 | 车站所在世界还没有调度图（或调度服务未接入） |
| 调度图里没有本站场的站台或股道节点 | 绑定的车站（或控制区的成员）在调度图里找不到；检查站码、控制区成员，或重建调度图 |
| 未找到绑定的控制区 | 控制区已删除，或屏幕所属运营商下没有这个代码 |
| 正在绘制站场图 | 第一次画这片站场，几何还在后台计算，下一次检查即显示 |
| 部分区间缺少轨道几何，列车位置可能显示不全 | 旧图没有轨道方块，重建调度图后恢复 |
