# 站场图屏（yard-3x5）

站场图屏把一个车站的站场画在 3×5 的地图屏上（640×384 像素）：轨道按真实走向画成横向示意图，按占用着色，车身与车次窗叠在上面，底部是图例。它是站台屏的一种布局，安装、绑定、主题和刷新都沿用站台屏。

只读：不改占用、不碰列车。将来的信号员控制台（`signalbox-3x5`）在它的基础上加操作，设计见 `docs/design/signaller-role.md`（本地设计稿，不入库）。

## 安装与绑定

1. `/fta pids give yard-3x5` 领安装纸，在挂满空展示框（3 行 5 列）的墙上右键。
2. 安装时自动绑定附近的车站；附近没有车站时和车站统屏一样不能安装。之后可以用配置棍或 `/fta pids set <屏幕> station ...` 改绑。
3. 装好后是测试卡，`/fta pids set <屏幕> mode live` 切到运行显示。没绑车站的站场图屏一直显示测试卡。

站场图屏不能与其他布局组合翻页（`PidsScreenPages#combinable`），也不轮播公告。

## 画哪些轨道

站场由调度图推出来（`YardArea`），不需要手工登记：

- 起点是本站的站台节点（`运营商:S:站:股道`）与咽喉节点（`运营商:S:站:股道:序号`）。
- 沿区间向外展开：道岔节点与无名目的地节点算在站场内，但离本站最近的站台或咽喉超过 256 格的不算。没有区间点隔开的正线因此不会把整条线卷进来。
- 碰到区间点、别的车站、车库或跨世界节点就停下，这条区间算出口，只画靠站场的 24 格，末端写去向（区间点取不是本站的那一端，按站名显示，查不到写站码）。
- 站场内节点超过 256 个时不再展开。

道岔节点的 ID 只有坐标、不带车站，所以只能这样按拓扑推。

## 怎么画

几何（`YardGeometry`）只依赖调度图快照，图重建、刷新或增补后才重算：

- 轨道取自建图时记下的每条区间的轨道方块（`rail_edges.footprint_json`，运行时从 `RailInterlockingState#footprintCellsByEdge` 取）。方块没有先后顺序，同一区间内前后左右相邻（高差不超过一格）的方块连成线段；斜向相邻的只在没有直角拐点时才连，台阶状轨道不会画成一串三角形。
- 区间没有轨道方块（旧图还没按新格式重建）时，用两端节点之间的直线代替，图左下角提示“部分区间缺少轨道几何”。重建调度图即可修正。
- 全部轨道点的主方向取最近的 45° 倍数后旋转成水平：正东西向是东在右、北在上，正南北向与斜 45° 的站场同样画成水平。
- 顺着轨道的方向按宽度铺满；垂直方向单独放大，每格最多 6 像素（常见的 4 格股道间距画成 24 像素）。这是示意图，不追求比例。

每次刷新（`YardProvider`）现取的部分：

| 画法 | 颜色（深色 / 浅色主题） | 来源 |
|---|---|---|
| 空闲 | 灰线 2 像素（`outline`） | 没有下面任何一种占用 |
| 进路锁闭 | 白 / 黑线 2 像素（`text`） | 区间（EDGE）资源上有 `MOVEMENT_REQUIRED` |
| 保护占用 | 暗红 `#993333` / 粉红 `#F27FA5` 线 2 像素 | 区间资源上有 `PROTECTIVE_RETAIN`、`HOLD_ONLY` 或 `PHYSICAL_FOOTPRINT`；与进路锁闭同时存在时按保护占用画 |
| 车占用 | 红线 3 像素（`red`） | 各节车厢所在的轨道方块（TrainCarts 的 `RailState#railBlock`），连续在图上的车厢连成一条 |
| 车次窗 | 面板色底、左边线路色条 | 车头上方；文字为车次号（按表运行时），否则为列车名；晚点超过 1 分钟琥珀色、超过 5 分钟红色（`Lateness`） |
| 股道号 | 次要文字色 | 站台节点上方 |

排队位、前瞻预览与解锁预约不画；节点（NODE）与冲突组（CONFLICT）资源不画。只画已加载、带调度标签的列车（`ManagedTrains#isFtaManaged`）。

## 刷新与开销

- 跟站台屏一样按 `pids.yml` 的 `render.check-interval-ticks`（默认 20 tick，即每秒一次）检查；内容标识（几何按对象身份、占用与列车按值）没变就不重画、不发送。
- 几何按图快照缓存，同一世界的各站共用一份按区间整理好的轨道方块。
- 每次检查读一遍全部占用（`OccupancyManager#snapshotClaims`）和本世界已加载的列车，都在内存里，开销在微秒级。车在动时每秒重画一次，只重发变化的地图块。
- 不做闪烁、不做悬停效果，避免持续重画。

## 布局键

```yaml
- type: yard
  x: 0          # 必填
  y: 32
  width: 640
  height: 232
  inset: 6      # 轨道距组件边缘的留白，默认 6；上方另留一行车次窗的高度
  label: 10     # 股道号、车次窗与去向的字号，默认 10
- type: yard-legend
  x: 0
  y: 264
  width: 640
  height: 120
  label: {size: 12, secondary: 10, gap: 6}   # 图例文字（中英文同行）
  note: 10                                    # 车次窗颜色说明的字号
```

站场图屏只能放站名（`station-title`）、时钟、站场图与图例；图例离开站场图会被拒绝。去掉留白后画轨道的区域不足 32×32 也会被拒绝。

## 屏幕上的提示

| 提示 | 原因 |
|---|---|
| 调度图未就绪 | 车站所在世界还没有调度图（或调度服务未接入） |
| 调度图里没有本站的站台节点 | 绑定的车站在调度图里找不到站台或咽喉节点；检查站码或重建调度图 |
| 部分区间缺少轨道几何，以直线代替 | 旧图没有轨道方块，重建调度图后恢复 |

## 代码

- `display/pids/yard/`：`YardArea`（站场推导）、`YardGeometry`（投影与线段）、`YardProvider`（缓存、占用与列车）、`TrainCartsYardTrains`（读 TrainCarts）、`YardPicture`、`PidsYardSource`。
- `display/pids/render/PidsYardPainter`：画站场图与图例；`PidsRenderer#renderYard`。
- `display/pids/view/PidsYardView`、`PidsYardViews`：一帧的视图；文案键 `pids.board.yard.*`。
- 接线在 `PidsService` 构造时 `PidsComposer#setYards`。
