# 车站信号员（signalbox-3x5、signalbox-4x8）

信号员值守一片控制区（信号楼）：在墙上的控制台上给要进入控制区的列车排列进路、扣车、改停股道、回复驾驶员与车掌的呼叫。控制台是站台屏的一种布局：`signalbox-3x5`（640×384，列车表 4 行），跨几个车站的控制区用 `signalbox-4x8`（1024×512，站场图 1016×300、列车表 6 行、按钮更大）；站场图部分与 `yard-*` 同一画法（见 `pids-yard.md`）。

信号员是“可选的增强”：没人值守时控制区是自动的，调度内核照常放行；有人值守时控制区转为人工，内核仍是安全的最后一道关，信号员只能把“放行”变成“暂不放行”。

## 上岗与下岗

1. 控制台：`/fta signal console give signalbox-3x5`（跨几个车站的控制区用 `signalbox-4x8`）领安装纸，在挂满空展示框的墙上安装；`/fta signal console set <控制台> operator <运营商>`、`zone <控制区>` 绑定控制区，`mode live` 切到运行显示。手持站台屏配置棍右键控制台打开的也是这份菜单。控制台不是站台屏：它借用站台屏的展示框画面与存储，但 `/fta pids` 不领控制台的安装纸、不管控制台（会提示改用 `/fta signal console`），控制台的命令也不管站台屏。
2. 有 `fetarute.signal.signaller` 权限的玩家（考过操作许可证上的信号员资格、正在考试或练习，或服主直接给了这个节点，见下文“信号员资格”）右键控制台，聊天栏出现 [上岗]，点它（即 `/fta signal on`，60 秒内有效）上岗。控制区随即转为人工；调度图未就绪时暂为自动，就绪后在控制台上按“人工/自动”转人工。
3. 一个控制区同时只有一名信号员；一名玩家同时只担任一个角色（驾驶员、车掌、信号员，见 `CrewDuty`）。
4. 下岗：`/fta signal off`；离开控制台 `console-range-blocks` 格以外超过 `grace-seconds` 秒；下线、死亡、换游戏模式；控制区被删除；插件关闭或重载。下岗时控制区回到自动，扣着的车放行，改停的股道撤销，在入口等的车立即重评。
5. 一切都只在内存里：重启与重载一律回到自动，不恢复许可。
6. 挂机：连续 3 列车由系统代排、其间信号员在控制台上没有任何操作，控制区转为自动（值守不变，提醒信号员可再转回人工），不让每列车都等满代排时限。任何一次控制台操作都把这个计数清零。

`/fta signal status`（信号员或驾驶管理权限）列出各信号楼的模式、值守者、在入口等的车、已给的许可与扣着的车。

## 进路许可闸

`dispatcher/runtime/control/SignallerGate`（零依赖 SPI，默认 `NONE` 恒放行），由 `SignallerGateCoordinator` 在下面几处、**内核本来会放行之后**问一次：

- 信号周期（`canEnter` 之前）、推进点、出站门控（`checkDeparture`）、折返接续、车库出车（`smartDepotAdmissionAllowsSpawn`）；
- 恢复层的 `reissueDestinationByName` 与 `forceRelaunchByName`（否则恢复层会绕过人工闸）；
- 不拦死锁疏通（`applyVerifiedSwitcherDrainAuthority`）。

判定：控制区为人工、这次申请的硬授权资源里有控制区资源、列车不持有控制区资源（不在区内）、也没有许可 → 拦下。控制区资源＝站场（`YardArea`）的节点、两端都在区内的区间、区内道岔的 `CONFLICT:switcher:*`；出入口区间（一端在区外）不算，否则停在入口外的车就成了“已在区内”。

被拦下的车：自建被拒的决定（`waiting-for-signaller`，空阻挡车），保留现有占用但不进控制区资源的排队，停因 `WAITING_FOR_SIGNALLER`，明细 `box=<运营商:控制区> since=<秒>`。空阻挡车不进等待图与互卡检测；健康层把它当计划内静止（`gate.waiting`），不重发、不清车。等待有上限：

- **超时代排**：在入口等满 `auto-route-seconds`（默认 20 秒，限 5–300 秒）由系统代排，记一笔“代排”，控制台提示并提醒信号员（聊天、动作栏加提示音），列车表这一行标“代排”；等到时限一半时先提醒一次。闸当场代排；每秒巡检也会兜底，但只给最近 6 秒内还来问过闸的车——更久没来问的多半被内核自己拦着，只唤醒它来问一次（之后至多每 10 秒唤醒一次），不记到信号员头上。取消一张许可时，原来在等的车按原来的开始时刻接着等，代排计时不清零；那段等待已过代排时限时提示“将立即代排”；
- **自动通过**：信号员对一条进路（同一入口、同一股道）设了自动通过，以后的车来了即放。车库出车、区内折返的车从区内起步，没有入口，以申请里第一条区内区间代替入口（同一条库线出来的车算同一条进路）；`DYNAMIC:` 停站要去的股道是暂定的、每列车可能不同，按候选里的第一条认，同一站的动态停站算同一条进路。转为自动时自动通过留着（自动模式下闸不读它），转回人工照用；下岗时清掉。

许可的生命周期：排列中（可取消）→ 车拿到控制区资源后锁闭（不可取消，之后内核按车尾出清逐段解锁）→ 车不再有区内的行车占用后作废。列车改名时许可随车迁移，拆下的新车没有许可；车销毁时清掉。发许可后放到下一拍重评这列车（闸可能在这列车自己的信号周期里当场代排，当场重评会重入）。

## 嵌套的控制区（车站控制）

同一时刻一片轨道只归一个信号楼管，与调度集中的中心控制、车站控制，地铁的中央控制、车站控制一样：

- **只能嵌套**：同一运营商的两个控制区，成员（车站、车库）要么不相交，要么一个整个包含另一个；部分重叠或一模一样都不行。`/fta signal zone add|remove` 改了以后会违反这一条时拒绝，并指出冲突的控制区。大区要移走小区里的成员，先从小区移走或删掉小区。
- **小区有人值守时由小区管**：大区让出小区那一片。大区的闸、“已在区内”、扣车与改停股道、控制台的列车表都只算剩下的部分；小区里的车不进大区的列车表，大区也改不了小区股道的停靠。
- **小区没人值守时大区代管**：大区照管整片，与没有小区时一样。
- **分界**：小区的出入口区间算大区的轨道。从大区往小区开、或从区外直接进小区，只等小区的许可；从小区出来进大区的其余部分，在分界等大区的许可（大区这时把分界区间当作入口认进路）。已在某一片里的车，那一片不再拦它。
- **交接**：小区上岗、下岗时当场重算各楼管的范围。已给的许可照旧有效；上岗前大区已放进小区方向的车，进小区前仍要等小区的许可。
- **控制台**：大区的站场图照画整个控制区，让出去的那一片用琥珀色虚线框围起来，框上写“小区名 · 车站控制（信号员）”。

判嵌套按调度图上的资源：同一运营商、同一张图上，资源整个落在大区里、又比大区小的另一个控制区才算嵌在里面。

## 中心工位（多人自动分区）

一个大区有人值守时，后来的人在设为工位的控制台（`/fta signal console set <控制台> workstation on`，存在站台屏表的 `workstation` 列）上岗，系统从大区剩下的部分切一片相连的车站给后来的人，成为一片**临时小区**；嵌套、让出、分界、交接都照上一节的小区算。不是工位的控制台照旧：大区有人时只提示有人值守。

- **临时小区**（`TransientZones`）：代码为“大区代码~序号”（序号从 2 起，取最小的空号），名字按 `signaller.workstation.name` 写成“大区名 · 工位 n”；只在内存里，重启、重载时与值守一起清空，不写进控制区目录，`/fta signal zone list` 里不列，`/fta signal status` 里名字后标“（临时）”。各处查控制区都先查临时登记、再查目录（`SignallerService#zoneOf`）。
- **流程**：点空工位 → 算出可分的一片，聊天提示“可为你划出：……（约占本区工作量 n%）[上岗]”；点上岗时按此刻的情况重算一遍再登记（大区持有人、成员、别的工位都可能变了）。一块工位只容一人，有人时提示“这块工位由某某使用中”。大区或这个人在考试、练习中时不分；剩下的不足两个单元时切不出来。
- **下岗**：临时小区随之撤销，那一片交还大区（大区有人时归大区那位，没人时转自动）。大区那位先下岗时，大区其余部分转自动，临时小区照常，在岗的工位收到提醒。大区被删、或管理员改了大区成员使临时小区不再全在大区里时，撤销这片，在岗的人下岗（控制区已调整）。
- **单元**（`ZoneUnits`）：每个成员车站、车库按自己推出一片站场（`YardArea`）；两片有共同节点、或一片的出口直接接到另一片里（只隔道岔、咽喉，例如车站和它的车库），合成一个单元，分界不落在道岔上；管理员划好、嵌在大区里的小区整体一个单元。一个单元的出口通往另一个单元的成员（中间只隔区间），两个单元相邻。
- **工作量**（`ZoneWorkload`）：按已发布的时刻表，接下来 `workstations.load-window-minutes`（默认 60）分钟内在单元里停站或通过的车次数（一个车次在一个单元里只算一次），加道岔数 × `workstations.switch-weight`（默认 0.5）。停靠点按调度图节点认，DYNAMIC 写法按写法里的车站、车库认；前一天发车、跨零点到站的也算。窗口内整个大区一个表定车次都没有（没有时刻表的线路、凌晨空窗）时，车次数换成站台股道与库线数。
- **切法**（`ZoneSplitter`）：目标为大区全部单元的工作量 ÷ 上岗后的总人数。从剩余部分的每个端头单元（在剩余部分里至多一个相邻单元）出发，沿相邻关系逐个加入（同时有几个可加时取编号小的），每加一个都不能把剩下的切成更多段（剩下的本就被别人管的那片隔成几段时照样能切）；各端头加出来的每一片里取工作量最接近目标的，平局取单元少的，再平取端头编号小的。没有端头（环线）时从离大区那位的工位最远的单元起切。已分出去的不重切。
- **控制台**：工位上有人值守时，那块屏画在岗那位的临时小区，标题写“工位 n”，副标题写所辖车站（最多三站，再多写“等 N 站”；标题栏放不下“大区名 · 工位 n”再加车站）。大区控制台上那一片的虚线框写“工位 n · 所辖车站（信号员）”。
- **成绩与记录**：每人一份班次，按各自的区计分。记录的控制区写临时代码，明细另记 `parentZone`（所属大区）。公开 API：上岗、下岗事件与信号楼概况的 `getParentZoneCode()`/`parentZoneCode`（见 `docs/dev/api.md`）。

## 扣车与改停股道

- **扣车**：只扣在区内停站的车。经 `StationStopCoordinator` 的第三个扣车来源（与按表扣车、联挂等候用 `later()` 合并），健康层随之豁免。最长 `max-hold-seconds`（不超过 150 秒，与按表扣车同一上限），到时自动放行；发车锁从到站起最长 180 秒，到站后过了一阵才扣的车可能被它提前放走。列车表上扣着的车画一条到扣车上限的进度条；到限放行、或车已不在站里停着（被提前放走）时都提示并提醒信号员。
- **改停股道**：只对 `DYNAMIC:` 停站、且候选股道都在本控制区里。`SignallerPlatformDesk` 由调度侧实现：信号员的选择优先于时刻表排定的计划站台，仅次于联挂搭档所在的股道；改选后撤掉已缓存的选台与节点替换，唤醒这列车；站台屏的站台变更沿用现有事件链。改不成时返回原因：已锁闭通往原股道的进路（过了分岔点）、或停站已开始与车已不在，控制台分别提示。

## 列车操作：越站与取消车次

控制台操作区第一页的「列车操作」把操作区换成选中车的第二页（1 列 × 3 行，与平时按钮同高）：越站、取消车次、返回。改选别的车、点空白处、点呼叫牌都回到第一页；回复呼叫与第二页互斥。信号员一侧经 `SignallerWorld#trains()`（`SignallerTrainDesk`）交给插件侧实现 `PluginTrainDesk`。

- **越站**：令晚点列车不停下一个停车站。
  - 条件：晚点不少于 `skip-min-delay-seconds`（没有时刻表的车判不了晚点，一律不行）；下一个停车站归本楼此刻管辖（`owned(box)`，嵌套口径）；考试中不行，练习中可以。
  - 规则在调度侧的 `StopSkips`：只认按交路进度往后第一个停车站；终点（`TERMINATE` 或最后一个停车站，也包括别的交路在那里终到的车站：短交路终点、折返站）、带动作指令（`CHANGE`、`COPL`、`DECP`、`DSTY`、`CRET`、`POWER`、`ACTION`）的站、交路在那一站换向的站不能越（`StopReversal`：把前后两段交路按调度图展开，站前最后一个节点与站后第一个节点相同就是换向；站节点接了三条以上区间、两头接的节点在同一侧、不在调度图上或走不通时一律不让越；DYNAMIC 停站每条候选股道都要直通；结果按图版本缓存）；叫来的车、联挂中的一体车、有乘务员在那一站上下车（领了任务等这一班的驾驶员或车掌、值乘到那一站交班的人，见 `CrewChanges`）也不能越；车已过为那一站刹车的起点（`SkipBraking`：舒适制动距离按 1 格/秒² 算，再加一半、至少 16 格的余量）后，越站与撤销都锁定。到站的路程取能算的里面最小的（最后经过的节点到站、到停车点的距离减去站到停车点）；控车诊断过期时，车在动或状态不明按已锁定算。
  - 下令后各读点把那一站当通过：调度的停车点与出站道岔前瞻、AutoStation 压牌（不停、不开门、到发照记、多模换模推迟）、ETA（`RouteStopPlan#withSkipped`：不累加它的停站，也不当下一个停车点）、站台屏这趟车成为通过行、乘客 HUD 与驾驶员、车掌的下一站跳过它。
  - 各处的指示：
    - 车内：车上所有人收到车内广播（聊天、副标题、提示音）；动作栏照常显示 HUD，没有另做保持。
    - 乘客 HUD：后续站点对话框与侧边栏里这一站保留、写“不停车”；默认模板在车站停站时多一行“某站不停车”，接近那一站时换成 `SKIP_PASSING` 状态（“列车通过 某站 本站不停车”，模板没写这一状态时照旧）。占位符 `skip_station*`、`skip_passing*`。
    - 站台：被越的站的站台屏把这趟车画成通过行，站台广播在聊天里播一次 `SKIPPED`（“因晚点本站不停车，请乘坐后续列车”，与取消共用开关）；进站时照常播通过。撤销后行恢复为停车行，不另播“恢复停车”。
    - 驾驶员：调度命令一条（动作栏与提示音）加聊天；侧边栏在信号一行下面加“调度命令 某站越站”，显示到过站或撤销。车掌侧边栏同样一行。
    - 控制台：列车表状态加“· 越站某站”。
  - 已令越站时越站键写“撤销越站”，刹车前可撤。
  - 越站令按调度逻辑名记在内存里，车开过那一站、换了交路、改名（随车迁移）、删车、开始新任务时清掉；重启即失效。查不到进度时（改名的间隙）只当没有令、不删。AutoStation 压牌时按牌子的节点认出本站（进度标签多半还停在上一个节点），后台站牌用取数那一刻冻结的越站令。下令与撤销时作废站牌与站台屏的缓存。
- **取消车次**：删车，交路转空缺并派替补，剩余停站登记取消（`VEHICLE_REMOVED`）。
  - 两步确认：按一下进入待确认（红底白字“确认取消 车次”），同一个人在 0.5 秒后、5 秒内再按一下才生效；换车、超时都撤销。确认后回到第一页，标题栏提示“已取消 车次”。
  - 不能取消：没有 `fetarute.signal.cancel`（随信号员权限授予）、考试或练习中、车不在区内（还在接近或在入口等着，多半停在邻区的站台上）、联挂中的一体车（先拆开）、车上有人而车不在站台上停稳（在站记录要对上车当前的交路与进度；人工驾驶的驾驶动作不算没停稳）。
  - 车上有人且停稳在站台：先扣住、插播停运通知（标题、聊天、提示音），倒计时 5 秒后结束驾驶员与车掌（任务记中断，原因 `signaller-cancel`），把仍在车上的人送到本站站台，再删车；倒计时中扣车键放不走车、再按取消不算第二次；车被改名时倒计时随车走；信号员下岗时就地办完（不然扣车随下岗解除，车会带着已被告知停运的乘客开走）。倒计时到时车已离开站台则作罢。车上没人时当场删。
  - 删车前记下这趟车当前的车次与预计晚点（`PidsService#holdCancelled`）：它在各站的取消行显示到计划到达按晚点顺延、再加 5 分钟，晚点车本站计划已过也照样上屏。登记只在内存，`/fta reload` 重建站台屏服务时接过。

## 呼叫

驾驶员与车掌都能呼叫这列车所在（或正接近、在入口等候）的控制区的信号员：

| 呼叫者 | 两短铃 | 命令 |
| --- | --- | --- |
| 驾驶员 | 车上没有车掌时，丢弃键（Q）连按两下 | `/fta drive call [signal\|doors\|obstruction]`，有没有车掌都行 |
| 车掌 | 车上没有驾驶员时，发车铃一秒内右键两下；车掌菜单的呼叫按钮同两短铃（此时写“呼叫信号员”） | `/fta guard call [signal\|doors\|obstruction]`，有没有驾驶员都行 |

两短铃（车掌也可点菜单的呼叫按钮）由 `SignallerCalls#buzz` 处理，驾驶员与车掌共用：列车停着时先问一次叫不叫得到（`SignallerLink#probe`，不排队）：叫得到就弹出对话框（`SignallerCallDialog`）选原因，信号前等候、车门故障、线路异常、一般联系，车在入口等候时信号前等候排第一，点一个就带着这个原因呼叫，取消或按 Esc 不呼叫；叫不到时直接说明原因、不弹框。行驶中不弹框（对话框打开时用不了快捷栏的手柄与按钮），直接按一般联系呼叫。对话框在服务器认出两短之后才打开，两短照旧按客户端时钟认；每个按钮只认一次，两分钟后失效。车上驾驶员与车掌都在时，两短铃是互相呼叫对方，呼叫信号员用命令。列车停在人工控制的控制区入口等候进路时（`SignallerLink#waiting`，即闸的 `waiting`），驾驶员与车掌的侧边栏多一行“信号员 入口等候进路”，写明此刻该怎么呼叫（两短铃或命令，按车上有没有另一名乘务员）；驾驶员手册「九、异常处置」也写了呼叫方法。驾驶员的丢弃键按一下发一个包（`BuzzerPress#forKey`）：两个包相隔超过 2 tick 就是又按了一下，快速连按两下也认得出两短；按住时系统先隔一段初始延迟再按键重复、密集连发，“一个包、隔一会儿、再一串包”算一次按住，不当两短。

呼叫带原因（`CallReason`）：信号前等候、车门故障、线路异常，没写原因为一般联系；没写原因、车又正在这片的入口等候时按信号前等候算。去处是 `SignallerLink#call(呼叫者, 岗位, 列车, 原因)`（岗位 `CallerRole`：驾驶员或车掌），返回 `CallResult`，呼叫者据此得到提示（驾驶员两短铃在动作栏、命令在聊天框；车掌两短铃与菜单在侧边栏，命令另发聊天框）：

- `CALLED`：已排进这片的待回复呼叫，提示写明哪片信号楼；写明了别的原因时换上新原因也算。
- `PENDING`：这名乘务员已在等这片的回复，不再排一条。
- `OUT_OF_ZONE`：有人值守，但列车不在这些控制区内，也没接近、没在入口等候；提示列出列车沿交路往后会经过的有人值守的控制区（按先后，最多 3 片，键 `out-of-zone-ahead`），认不出交路或前方没有时不列。“在区内、正接近”与列车表同一口径（`SignallerService#concerns`）。
- `NO_SIGNALLER`：没人值守。`UNAVAILABLE`：信号员功能关着或模块没接上。

`SignallerCalls`（驾驶模块，驾驶员与车掌共用）按乘务员算 5 秒冷却：冷却期内的重复呼叫不再转给信号员，沿用上一次的结果；写明了别的原因照转；上一次没人接时不合并，车开近了马上再叫就能叫到。信号员这边按“列车加呼叫者”排队：同一列车的驾驶员与车掌各排各的，回复与漏接各回各的；同一名乘务员已在等回复时，后来写明的原因替换先前的（排队位置不变）。

控制台标题栏出现呼叫牌，写着车次、谁在呼叫（驾驶员或车掌）与原因；来电提醒（聊天与动作栏）写明“列车 X（驾驶员/车掌 名字）呼叫信号楼”。信号员点呼叫牌，操作区换成四条固定回复（前方有车请等待、进路正在排列、请以注意速度运行、已收到），同时选中呼叫的车；回复以聊天与动作栏发给呼叫的那名乘务员。回复要配得上原因（`CallReplies`）：信号前等候按回复那一刻的实况判——此刻能给它排进路（车没被扣、没在停站，前方区内也没有别的车占着）该回“进路正在排列”，排不了该回“前方有车，请等待”，真人呼叫与模拟呼叫都这样判；车门故障回“已收到”，线路异常回“请以注意速度运行”，一般联系哪条都行。回了“进路正在排列”就要兑现：20 秒内（`SignallerService#PROMISE`）没亲手给它排进路（信号员排列或自动通过算，系统代排不算），补记一次答错并告诉信号员；区转了自动、车被删时不再追究，车改名时跟着走。回错照样发给呼叫者，但记一笔答错，标题栏提示“回复与呼叫不符”，聊天里告诉信号员该怎么回。`call-timeout-seconds` 内没回复算漏接，告诉呼叫者信号楼没回复。回复面板对着的呼叫一旦出队（超时、车被删），面板退回按钮，回复不会落到排在后面的乘务员头上。

模拟呼叫（`SignallerService#drillCall`，操作许可证的练习与考试用）：以列车表里一列车的名义（按驾驶员）来一次呼叫，在入口等候的车按信号前等候，其余随机车门故障或线路异常；回复与漏接都不发给任何人，考官听到的是 `DRILL_*` 事件。已有待回复的呼叫时不来。真乘务员呼叫同一列车时另排一条，不并进模拟呼叫；车改名时呼叫的原因与模拟标记跟着走；用的车被收车、删掉时呼叫撤掉，考官收到 `DRILL_CANCELLED` 再来一次。两短铃之后马上用命令写明别的原因，不受 5 秒冷却限制。

## 值守中的模拟事件

服务器人少时，信号员大部分时间只看着系统排进路。`SignallerEvents` 隔一阵以一列与本楼有关的车的名义来一次呼叫（常驻模拟呼叫），原因与答案都按那列车此刻的实况；事件一律不改变列车运行，只考判断与沟通。

- 出题条件：有人值守，不在考试或练习中，人在控制台范围内，上岗满 60 秒，本楼没有待回复的呼叫，也没有回了“进路正在排列”还没兑现的模拟呼叫。
- 间隔：按 `events.mean-interval-seconds`（默认 300）取指数分布，两题至少隔 `events.min-gap-seconds`（默认 90）；第一题从上岗满 60 秒起算，到了时刻条件不满足就等到满足。随机数由服务注入（`SignallerService#setRandom`），测试可以固定。
- 挑车：不借有真人驾驶员或车掌的车（`SignallerWorld#crewed`）。在入口等许可的报信号前等候，被扣在站里的询问前方情况（`CallReason.QUERY`，判法同信号前等候），在区内停站的报告在哪一站、哪一道停妥（`CallReason.REPORT`，回“已收到”）。询问与报告只给模拟事件用，乘务员的对话框与命令里没有（`CallReason#crew`）。
- 模拟呼叫沿用呼叫牌与回复页，回复与超时都不发给任何人。真人的呼叫排在模拟呼叫前面；排到了正在回复的模拟呼叫前面时回复面板退回按钮。车跟本楼无关了（出区、不在列车表里）、信号员下岗时，模拟呼叫直接撤掉、不计超时。
- 计数另记（`simRight`、`simWrong`、`simMissed`，记录明细同名键），不混进真呼叫；考官事件 `SIM_RIGHT`、`SIM_WRONG`、`SIM_MISSED`。结算时出过题的班次多报一行“模拟事件：答对、答错、超时”。

## 控制台

`SignalboxConsole`：站台屏每次检查按（运营商，控制区）取一帧 `SignalboxState`，同一拍内各屏共用；点击由站台屏做命中测试后以 `ConsoleTarget` 交回。没在值守的玩家点任何地方都是请求上岗。

操作：

- 按不了的操作不静默忽略，标题栏提示原因：没选车、自动模式下由系统放行、已有许可、已在区内、没有可取消的进路、进路已锁闭、未停站、已在扣车、未被扣车、认不出入口等。
- 按住右键时客户端每 4 tick 重发一次交互：紧跟上一次点击 0.35 秒内的点击都算连发、一律不算（选车除外），连发不断时一直顺延，所以按住一个键只算一下。否则会刚转自动又转回人工、刚扣的车又被放走、翻到第二页后连发落到“取消车次”上把车删掉。灰显的按钮被按到只提示原因。
- 扣车与放行是同一个键：选中的车被扣着时写“放行”，再按放行。
- 排列进路后自动选中下一列在入口等的车（按等候先后），连着处理几列车时每列只要按一下。
- 选中车的进路已设自动通过时，自动通过按钮写“取消自动通过”。点没有车在等、旁边写着 “A” 的入口信号，撤掉这个入口的自动通过。
- 选中的车跟这座楼没关系了（出了区、不在列车表里）5 秒后清掉选择，同名的车下一趟回来不会被自动选中。
- 调度图未就绪时闸对这片控制区一律放行：模式牌按“自动”画，标题栏常驻“调度图未就绪，暂为自动”。

列车表的范围：在区内（最近经过的节点在区内或有区内占用）、正接近、在入口等、有许可或被扣着的车；正接近指下一个途经点在区内，或往前的途经点在下一个区外停车站之前就进区（停在区外最后一站、或从那一站开出来、中间只隔着区间点，`SignallerService#approaching`）——区外车站与控制区之间隔着几个区间点时，车一出那一站就算接近，不必等它开过入口前最后一个区间点（那时它往往已在入口被闸拦下）。

提示音（`SignallerMessenger#cue`，只在人工模式下）：有车开始接近时一声轻响，有车停到入口等候时低两声，动作栏写出车次，不进聊天栏；上岗（或转回人工）时已在接近的车不响，一列车接近一次只响一次。

排序为等许可、排列中、扣车（扣车有上限）、接近、已排、停站、区内。画不下的车数在表头右端写 “+N”；选中的车排在画不下的地方时顶替最后一行。晚点直接读时刻表已有的数，不在刷新时算 ETA。

预显示（浅蓝）与排列中（白色虚线）的进路由 `RouteAhead` 把交路从当前位置起的途经点按最短路展开得到（按图快照记忆），只用于显示与认“同一进路”，不参与放行。

## 成绩与奖励

按班次结算（`SignallerShift` → 驾驶模块的结算实现）：

- 经手按“拿着许可驶入（锁闭）”计次，同一列车往返两次算两次；代排、自动通过与预排命中也都在驶入时按许可来源计。
- 成绩（`SignallerScore`）：满分 100，超时代排、漏接呼叫、回复与原因不符每次扣 5；在区内丢了时间（驶入时与出区时比，晚点多出 60 秒以上）每列扣 2；交汇排序不当每次扣 3；模拟事件答错或超时每次扣 2（系统随机出题，比真呼叫轻）。
- 正点与丢时间：许可锁闭（驶入）时记下这列车的晚点与读数版本（`TimetableService#delayStamp`：车次加已记的到发次数），出区（许可作废）时再取一次；多出（减去在区内被扣车的秒数）不超过 30 秒、又是亲手排进来的计正点放行，多出 60 秒以上的计在区内丢了时间。查不到晚点（没有时刻表）、或其间没有新的到发记录（只经过道岔区、区内不停站，读数没更新）的车不计。
- 交汇排序：信号员给一列车排进路时，另一个入口还有车在等、两车区内要走的路有交汇（共用道岔或股道），这两列记成一对；两车都出区后看合计多出的晚点：不超过 60 秒算得当，超过 180 秒算不当。快车优先、晚点车先走都体现在这里：排得好两车都少晚。一车没有时刻表、20 分钟内没都出区的不计。
- 奖励按亲手排的车计（不含代排与自动通过，免得设满自动通过挂机刷奖励），预排命中、正点放行各加半列（都不超过亲手排的车数），交汇排序得当加一列，模拟事件答对各加半列；计单价后乘评级系数。结算时另报一行明细：预排、正点放行、区内晚点、交汇得当与不当、答错。

在区内被令越站的车出区时不评正点放行与丢时间，所在的交汇也不评（越站省下的时间会让这几项虚高）。取消车次与令越站只记次数（班次计数 `tripsCancelled`、`skipsOrdered`，记录明细同名键），不加分也不扣分。

记录写进 `drive_task_records`，`mode = SIGNALLER`，时刻表与车次用哨兵值；驾驶排行与驾驶员汇总排除车掌与信号员。考试的这一班写记录、不发奖励、不另报这一班的成绩（考官按考试标准讲评）；练习的这一班不写记录也不发奖励（`SignallerShift#examined`、`#practiced`，下岗时向考官问清）。

## 信号员资格（操作许可证的信号员考法）

操作许可证上驾驶、车掌、信号员三个岗位并列（`LicenseClass#post`），信号员不占驾驶的级数，不要求先有别的资格。`drive.yml` 的 `license.classes.signaller`：考法 `exam: signaller`（`LicenseClass.Exam.SIGNALLER`），考过给 `fetarute.signal.signaller`；默认 `exam-trains` 5（信号员读这个键，不读 `exam-stops`）、及格 `min-points` 70，报名前要做完 `training-runs`（1）次练习。已有服务器的 `drive.yml` 会补上这一项（补缺失键）。

- 考官：`SignallerExaminer`（信号员模块的接口，操作许可证服务的 `SignallerExams` 实现，`wireSignaller` 接上）。信号员服务把上岗（控制区名、是否已转人工、区里有没有车站）、下岗原因和值守中的每件事告诉它：转人工、转自动、被系统转自动、选车、亲手排进路、三种来源的车驶入（亲手排、代排、自动通过）、扣车、放行、设与撤自动通过、来了呼叫、回复、漏接、改停股道。考官出错只记一笔，不影响值守。
- 报名：`/fta license exam signaller`、`/fta license practice signaller`。信号员功能关着时不能报名；正在担任别的角色、领着任务时也不能（`LicenseService#crewBusy`）。报名后登记考试（截止为 `license.exam-window-minutes` 之后），临时挂上信号员权限，发一本《FTCA 信号员手册》（`DriverHandbook#signaller`，`/fta handbook signaller` 再领）。还没上岗时 `/fta license abandon` 放弃；正在值守时要先下岗。
- 考试（`SignallerExam`）：从上岗（转人工）起，亲手排的进路上驶入控制区的车计数，满 `exam-trains` 列交卷；走自动通过的不算。亲手排到第几列时（随机）来一次模拟呼叫，排满时它还没了结（回复或超时）就等它了结再交卷。满分 100，代排、漏接、答错各扣 10 分（比平时值班严一倍），掉到及格线以下当场不及格；中途按“转为自动”、或因连续代排被系统转为自动，当场不及格；排满之前下岗、或到了截止还没排满，不计成绩、可以马上再考。判定后（及格、不及格、作废都一样）下一拍以 `EXAM` 结束这一班：要继续值守就重新上岗；临时权限在这一班结算之后收回，所以结算时这一班还算考试。不及格进入 `retry-cooldown-minutes` 冷却。
- 练习（`SignallerTutorial`，带练）：上岗后一步步提示（聊天带进度、副标题一句、每分钟提醒一次）：上岗、认识控制台（读 12 秒自动继续）、人工模式、选车、排列进路、扣车、放行、自动通过、取消自动通过、回复呼叫（讲到这一步时来一次模拟呼叫，回错或超时就再来一次，直到回对；先前回对过真的呼叫就当场完成）、下岗。先做的事也算；控制区里没有车站时扣车、放行两步跳过。情境提示（每次练习每种一次）：来了呼叫、被代排、漏接、转为自动、被系统转自动。全部做完并用 `/fta signal off` 下岗计一次练习，讲评按考试标准折算这一班的得分；以别的方式下岗不计次，列出还差的步骤。练习在截止之前要上岗，上岗后练到下岗为止。

## 接近锁闭

车已在接近（或已停在入口等候）时取消它的进路，这个入口进入接近锁闭（现实的时间锁闭）：`approach-lock-seconds` 秒内这个入口排不了进路（标题栏提示锁闭中），系统代排与自动通过也等它。锁一过：设了自动通过的走自动通过；代排时限在锁闭期间就到了的车由系统放行（许可来源 `RELEASED`，不算代排、不计经手，信号员不因取消进路受罚，等待照样有上限）；其余照常。车还要先在区外别的站停（提前排的进路）时取消不锁。转为自动、下岗时锁随之清掉。

## 配置（`config.yml` 的 `signaller` 段）

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关闭后控制台只读，没有人工控制 |
| `auto-route-seconds` | `20` | 入口等许可超时代排；限 5–300 秒，等待一定有上限 |
| `console-range-blocks` | `32` | 离控制台多少格以内算在岗 |
| `grace-seconds` | `30` | 离开范围后多久下岗 |
| `max-hold-seconds` | `150` | 扣车上限（不超过 150） |
| `call-timeout-seconds` | `60` | 呼叫多久没回复算漏接 |
| `notice-seconds` | `3` | 控制台临时提示显示多久 |
| `approach-lock-seconds` | `30` | 接近锁闭：车已在接近时取消进路，入口要过多久才能再排；0 为不锁，限 0–180 |
| `skip-min-delay-seconds` | `180` | 晚点至少多少秒才能令越站；限 0–900 |
| `events.enabled` | `true` | 是否出值守中的模拟事件 |
| `events.mean-interval-seconds` | `300` | 平均隔多少秒出一题（指数分布） |
| `events.min-gap-seconds` | `90` | 两题至少隔多少秒 |
| `workstations.enabled` | `true` | 是否在中心工位上切临时小区；关闭时工位与普通控制台一样 |
| `workstations.load-window-minutes` | `60` | 估工作量时统计接下来多少分钟的表定车次（1–1440） |
| `workstations.switch-weight` | `0.5` | 每个道岔折算的车次 |

## 已知限制

- 信号楼不跨服；控制区落在服务器边界时以后再说。
- 编表与 ETA 都假设自动运行：信号员扣车或晚排进路会让站台屏的时刻偏早。
- 区内造成的晚点增量、预排命中加分尚未计入成绩。
- 叫来的车一律不能越站（比只禁叫车目的站更保守）。
- 换向判据会误拒：交路的路径点写在了错股道上、图上只能绕回去时（路径点前后看是直通、展开后像折返），这一站越不了。
- 信号员练习在真实车流上带练：控制区里一直没车来时，排列进路、扣车等步骤做不了，只能等车或换一片控制区。
- 闸在 `canEnter` 之前问：代排之后内核仍可能因进路被占不放行，这段等待照样记在代排名下。
- “在区内”只认区内的行车占用（进路锁闭、车身所在）与区内区间上的停车保持；保护占用与道岔冲突上的停车保持不算，免得停在出入口外端的车不经许可进区。
- 接近的车之间按车次排，没有按离入口的远近排。
- 中心工位的工作量只是估计：同一车次在一个单元里只算一次，取消的车次也算；切分只在上岗那一刻算，之后时刻表变了不重切。
